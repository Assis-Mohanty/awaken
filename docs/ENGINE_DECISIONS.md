# Engine decisions — resolutions of GAME_DESIGN ambiguities

GAME_DESIGN.md stays the source of truth for numbers. This file records how `:engine` resolves places where the spec is
silent or self-contradictory. No new numbers are introduced here. If a decision is overturned, change the engine and
its tests, and delete the line. Rows marked **Approved** were signed off by the product owner (2026-10-18) and are now also written into GAME_DESIGN.

| # | Topic | Spec says | Engine does |
|---|---|---|---|
| 1 | Main/side difficulty | §6.3 "HARD adjusted by tier" and §6.1 "Side: Normal"; §6.4 "main uses tier+1" | Side = `tier(stat)`, main = `tier(stat)+1` capped at EXTREME. Default tier NORMAL gives Normal sides and a Hard main. |
| 2 | Streak for `S` | "streakDays" | The streak folded over **finalized** days. Completions today never raise their own multiplier. |
| 3 | Cap vs crit | — | The cap test uses the full XP *including* crit. A capped quest gets `round(xp×0.25)`, 0 gold, and stat XP from the reduced XP. A crit fragment is still granted (cosmetic). |
| 4 | `HEALTH_*` verification | §6.2 lists 3 variants | All map to `V = 1.30`, uncapped. |
| 5 | Secondary stat | "30 %" | `round(awardedXp × 0.3)`, half-up like all rounding. |
| 6 | Weights | "focus 2.0, neglected 1.5, else 1.0" | Weights multiply (focus + neglected = 3.0). Neglected = no completion in that stat for ≥ 3 game-days, or never. Two-stage pick: a stat by weight, then a template uniformly within it, so stats with more templates aren't favoured. |
| 7 | Main stat fallback | `focusStats[gameDay % 2]` | `gameDay` = `epochDay`. If that stat has no eligible templates, pick from the whole pool by weight. Sides avoid the main stat when possible and never repeat a template. Filters (equipment, injury, health, novelty) are never relaxed; the generator returns fewer than 4 only when the filtered pool is smaller. |
| 8 | Instance ids | "fresh UUID" | **Approved; in GD §4.2, §6.3.** `UUID.nameUUIDFromBytes("hunterId\|gameDate\|slot")`, which is deterministic. Regeneration is idempotent and crits can't be re-rolled. Slots: `main`, `side0..2`, `rerollN`, `penalty`. |
| 9 | Hashes | `hash(hunterId, gameDate)` | `fnv1a64("hunterId\|yyyy-MM-dd\|purpose")`, where purpose ∈ directive / rerollN / penalty. The crit hash is over the lower-cased id's UTF-8 bytes; `mod 10 000` is unsigned. |
| 10 | Rerolls | "1 free … further cost 40 (max 3/day)" | **Approved; in GD §6.3.** The first reroll is free; reroll numbers 2–4 cost 40 each. "Max 3" counts paid rerolls, matching the §9.2 shop row. |
| 11 | Injury / recovery / penalty pools | "e.g. impact, legs"; "VIT/WIL low-impact"; "penalty template set" | Injury excludes tags `impact`, `legs`. Recovery keeps only VIT/WIL templates without `impact`, and the main quest rotates VIT/WIL. The penalty set is templates tagged `penalty`, which are never used for normal generation. |
| 12 | Streak fold | §7.2 | **Shield-only-when-streak>0 approved.** A cleared day is always +1, even on a rest or recovery day. For an uncleared day, protections apply in this order: rest → recovery (monthly budget) → shield → BROKEN (reset + penalty flag). A shield is used only when streak > 0. Every recovery-flagged day uses up budget. Unopened days are treated as uncleared, empty days. |
| 13 | Cleared-day items | "any type" | Counts main, side, habit, penalty, trial and gate completions. |
| 14 | Rank Trial | §5 | Only the next rank can be challenged. Stages = two weakest stats by XP plus the first focus stat not among them; if both focus stats are among the weakest, the third stage uses the third-weakest stat. Ties go by enum order. One stage per game-day, inside a 5-game-day window. A retry is allowed 48 h (wall clock) after the failure. |
| 15 | Achievements | "launch set: 30" | **32 approved; GD §10 fixed.** The §10 table lists **32**; all are implemented. Streak achievements use the best streak. Dawn Raid = local time in `[dayStartHour, 07:00)`; Midnight Gate = `≥ 23:00` or before `dayStartHour`. `rank_*` award 0 gold (the trial pays 500). Titles are ids; display text lives in `strings.xml`. |
| 16 | Adaptive window | "previous 7 days" | The 7 game-days before the recalibration Monday, even when the first open is later in the week. REROLLED quests are ignored. |
| 17 | Undo → re-complete | §6.5, §9.3 | **Approved; in GD §9.3.** Each completion attempt has its own `completionId = questInstanceId#attemptN` (N from 1, `LedgerMath.completionId`). Ledger `sourceId` = completionId; undo rows are `(UNDO, completionId, same kind/stat/item)`, so a double undo is a no-op. The crit seed stays the questInstanceId, so re-completing never re-rolls a crit. Re-completion is priced again, including daily caps; the app derives today's capped XP from the net ledger, so undone XP doesn't count. Tests: `CompletionAttemptTest`. |
| 18 | Sleep template targets | Phase 3 content spec: "HEALTH_SLEEP 7h baseline only for VIT" vs "targets increasing" | One VIT-only `HEALTH_SLEEP` template (`vit_sleep`) with 7 h at every difficulty. Sleep targets may be equal across difficulties; every other template must be strictly increasing. |
| 19 | Template library format | GD §6.2 shows one template | `templates.json` is `{version, equipment[], tags[], units[], templates[]}`. The vocabularies are checked by `TemplateLibrary.validate()`, so a typo in a tag or equipment id fails tests instead of silently filtering templates. The 15 `penalty` templates are extra, beyond the ≥150 regular templates (≥25 per stat). |
| 20 | Manual completion | — | **Approved; in GD §6.5.** Only SELF quests can be completed by hand. HEALTH quests complete from Health Connect data, TIMER quests from a cleared Focus Gate, both through a separate verified entry point. |
| 21 | Undo vs achievements | — | **Approved; in GD §6.5.** Undo never revokes achievement unlocks or their gold. |
| 22 | Daily caps in the data layer | §4.3 | Each completion attempt is a `completion` row. Quest XP ledger rows carry `xp_source` (SELF/TIMER/HEALTH); undo rows copy the original's `game_date` and `xp_source`. Today's SELF/TIMER XP = the net sum for the game-date, so undone XP doesn't count toward the cap. |
| 23 | Derived streak | Invariant 7 | Each finalized `day_record` stores its outcome. `StreakRules.replay(outcomes)` rebuilds streak and best streak without shield history. The recovery budget used in a month = min(7, finalized recovery-flagged days in that month). |
| 24 | Day-clear gold and penalty issue | §7.3, §9.1 | +20 gold is awarded when a CLEARED day is finalized (sourceId = game-date). A rollover that finalizes at least one BROKEN day adds one penalty quest for today (deterministic id, so it's never duplicated). |
| 25 | Undo across day start | §6.5 "undoable for 10 minutes" | Undo is refused (`DayClosed`) once the completion's game-day has ended, even inside the 10 minutes: finalized days are never re-opened (ARCH §3.2). Example: complete at 03:55, try to undo at 04:01 → refused. |
| 26 | Haptics without VIBRATE | DESIGN_SYSTEM §2.6 names `VibrationEffect` primitives (`PRIMITIVE_THUD`, `PRIMITIVE_CLICK ×2`) | The `Haptics` wrapper uses `View.performHapticFeedback` constants only (CLOCK_TICK, CONFIRM, CONTEXT_CLICK ×2, LONG_PRESS, REJECT). This needs no VIBRATE permission and follows the user's system touch-feedback setting. Trade-off: level-up uses LONG_PRESS, which is weaker than THUD. Switching to Vibrator compositions later means adding the (install-time, normal) VIBRATE permission. |
| 27 | IBM Plex Sans file | Phase 5 prompt: static 400/500/600 TTFs | google/fonts now only ships `IBMPlexSans[wdth,wght].ttf` (variable). It is bundled once as `res/font/ibm_plex_sans.ttf`, and `FontVariation.weight(400/500/600)` pins each weight (supported from API 26; minSdk is 28). Saira Condensed is still static SemiBold/Bold. OFL texts are in `assets/licenses/`. |
| 28 | First-directive starter | Phase 6: "first directive guarantees one EASY quest in a focus stat"; DS §4.1 "doable now" | On the hunter's first game-day, `side0` is an EASY, SELF, non-`outdoor` template in a focus stat (weighted pick, novelty and filters still apply). The main quest and the other two sides are unchanged. Recorded in GD §6.3. |
| 29 | Daily System line | GD §11 "keyed by context, deterministic by date" | Priority: comeback (penalty open) → trial_active → streak_milestone → cleared_day → neglected_<stat> → generic. Milestones are the streak achievement thresholds 3/7/30/100 (GD §10), so no new numbers. "Neglected" here means a stat that was active before and has been idle ≥ 3 game-days; never-touched stats don't count. Pick = fnv1a64(hunterId\|date\|context) mod lines. |
| 30 | "Why this quest?" | DS §4.3 example "INT neglected for 3 days" | `QuestReasons.reasonFor`. Main → "today's focus stat"; penalty / habit → fixed lines; trial stages and gates → none. Side quests, highest first: stat never trained → "new"; idle ≥ 3 game-days (`NEGLECT_DAYS`) → "neglected for N days"; focus stat → "focus"; else "balance". Same signals as the generator's weights (#6), no new numbers. |
| 31 | Rank Trial stages | §5 "one Hard quest per day … any order, within 5 days" | **Approved (all open stages offered).** While a trial is ACTIVE, each game-day gets one Hard TRIAL quest per uncleared stage stat (`DirectiveGenerator.trialStages`, slot `trial-<STAT>`, SELF templates preferred; recovery mode and novelty don't apply). Completing one closes that day's other stage quests (EXPIRED). Stage clears are derived from completed TRIAL quests inside the window (`RankRules.clearedStages`): one per stat, one per day; no extra column. Pass → trial PASSED + `GOLD +500, TRIAL, sourceId = trialId` in the same transaction. Fail time = start of the game-day after the window (`trialFailedAt`); the 48 h cooldown runs from there. |
| 32 | Undoing a trial stage | §6.5 undo vs §5 promotion | **Approved.** The completion that turned a trial PASSED cannot be undone (`RankRules.canUndoStage`): promotion is permanent, like achievements. Earlier stages stay undoable. |
| 33 | Recovery Mode duration | §7.2 "pauses streak for up to 7 game-days per calendar month" | Recovery Mode is a mode, not a single day: turning it on flags today; each rollover carries it to the new day while the previous day was flagged and the new day's month has budget left (`StreakRules.recoveryContinues`). It ends when the hunter turns it off or the budget runs out. |
| 34 | Focus Gate pause | §8 "Up to 1 pause of ≤ 5 min allowed per run" | **Approved.** The one pause stops the countdown (the end moves later by the pause length), and time away from the app while paused does not use the breach budget. At 5:00 the gate resumes on its own; it never collapses for an over-long pause. `GateRunMath.pausedDuration` / `pauseEndsAt`. |
| 35 | Gates across the day start | — (a quest belongs to one game-day) | **Approved.** A gate may start only if `now + duration + 5 min` is at or before the next day start (`GateRunMath.canStart`); otherwise its tile is disabled. If a claim still lands after the day closed (the rollover expired the quest), the run collapses with reason DAY_RESET and pays nothing. |
| 36 | Undoing a gate clear | §6.5 undo vs §8 timer verification | **Approved.** A cleared gate is final: `UndoCompletionUseCase` returns `GateClear` and the reward snackbar shows no Undo. |
| 37 | Gate background accounting | §8 "background > 90 s cumulative"; ARCH §3.3 | Background time is measured in elapsed realtime (immune to wall-clock changes) from the stored stop to the return, so a process killed while away is measured on the next start. A different boot count (or a lower elapsed reading) makes it unknowable → COLLAPSED "Device restarted". Time after the planned end does not count, so leaving at the end and claiming later is fine. Phone-call exclusion is not implemented (§8 "otherwise just the 90 s budget"). Stats offered: INT (default), WIL, CHA, STR; VIT is not offered. |
| 38 | Status radar | Phase 9 prompt "this week vs last week stat XP gained" vs GD §2 "stat level on the radar, axis max = max(20, highest + 5)" | **Approved (user, 2026-10-19).** The radar plots stat **levels**: the solid polygon is now; the dashed polygon is levels from ledger rows dated before this week's Monday. Axis max follows GD §2 over both polygons (`StatusMath.radarMax`). Weekly XP gains appear in the Weekly Report. |
| 39 | Heatmap intensity | DS §3 "cleared intensity 0–4" (steps undefined) | **Approved (user, 2026-10-19).** Intensity = active (not undone) completions on the game-day, capped at 4 (`StatusMath.heatmapIntensity`). Weeks run Monday → Sunday, 18 of them ending with the current week. Rest days are outlined. |
| 40 | Weekly Report | GD §11 "stats gained, best day, most-neglected stat, next-week recalibration" | Covers the current Monday–Sunday game-week; it opens on game-day Sunday (always available in debug builds). Stat gains are net `XP_STAT` (undo nets out). Best day = most net `XP_TOTAL`, ties to the earlier day, none if no XP. Most neglected = lowest gain, ties by stat order. The recalibration line is `DifficultyAdapter.recalibrate` over this week's quests as if next Monday ran now, labelled "projected". |
| 41 | Chapter reveal | GD §11 "each unlock = full-screen reveal" | Shown in the reward chain after the level-up ceremony for every chapter whose `unlockLevel` falls in `(levelBefore, levelAfter]`, then the rank-up ceremony. Nothing is persisted: unlocked chapters can be re-read from Status. Debug "grant level" skips the chain. |
